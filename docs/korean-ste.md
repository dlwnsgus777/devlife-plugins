# korean-ste

기술 문서용 통제 한국어 규칙입니다. 항공 정비 문서용 통제 영어인 ASD-STE100을 한국어에 맞게 옮겼습니다.
문서 하나 안에서 같은 대상을 같은 표현으로 쓰게 맞추고, 런북·장애 보고서처럼 읽고 바로 따라 하는 글은 문장을 짧게, 한 문장에 지시 하나만 담게 고칩니다.
셀 수 있는 규칙은 린터(`scripts/lint.py`)가 검사합니다. `writing-check`가 점검 중에 이 스킬을 부르고, 단독으로도 씁니다.

## 언제 사용하나요?

- 문서 안에서 용어·말투·단위·코드 표기를 하나로 맞추고 싶을 때
- 런북, 장애 보고서, 오류 메시지, 릴리스 노트, 프롬프트·스킬 지시문을 쓰거나 점검할 때
- `writing-check`로 슬랙 메시지나 문서를 점검할 때 (자동 호출)

> 마케팅 글, 블로그 글, 문체만 다듬는 작업에는 쓰지 않습니다. 문체는 `korean-humanizer`가 맡습니다.

## 트리거 문구

```
"용어 통일해줘"
"표현 통일해줘"
"일관성 맞춰줘"
"korean-ste"
"런북 점검해줘"
"장애 보고서 점검해줘"
"오류 메시지 다듬어줘"
"릴리스 노트 점검해줘"
```

## 지키는 규칙

- 점검 대상은 이번에 새로 쓰거나 덧붙이는 글뿐이다
- 기존 문서에 덧붙일 때는 덧붙이는 부분만 점검하고 고친다
- 파일에 이미 있는 내용은 고치지 않는다

## 실행 흐름

1. **적용 수준 정하기** — 글 종류에 따라 정합니다.

   | 수준 | 글 종류 | 적용 규칙 |
   |---|---|---|
   | `strict` | 런북, 장애 보고서, 오류 메시지, 릴리스 노트, 프롬프트·스킬 지시문 | 일관성 + 문장 규칙 전부 |
   | `standard` | 슬랙 메시지, 일반 문서(컨플, PR 설명, 지라) | 일관성 + 문장 길이 25어절 |
   | `consistency` | 메일, 리뷰 댓글, 그 밖의 글 | 일관성만 |

2. **용어 지도 만들기** — 파일에 이미 있는 내용까지 문서 전체를 읽고 그 용어를 기준으로 만들되, 새로 쓰는 부분에만 적용합니다. 덧붙일 때는 기존 내용의 말투도 따릅니다. 같은 대상을 가리키는 표현을 묶고 대표어를 정합니다. 대표어는 프로젝트 용어집 `docs/glossary.md`에 있으면 그것을, 없으면 문서에서 처음 쓴 표현을 씁니다. 사용자가 확인한 뒤에 적용합니다.
3. **린터 실행** — 일관성 규칙(`TERM`·`STYLE`·`UNIT`·`CODE`)과 문장 규칙(`LEN`·`MULTI`·`COND`·`VAGUE`)을 줄 번호와 함께 찾습니다. 기존 문서에 덧붙일 때는 덧붙이는 부분만 임시 파일로 빼서 실행합니다.
4. **고치기** — 린터가 찾은 항목과, 읽어서 확인하는 항목(지시마다 대상 명시, 장애 보고서의 시각·수치·원인, 오류 메시지의 해결 방법)을 고칩니다. 모르는 조건이나 값은 `[확인 필요]`로 표시합니다. 문장을 나눌 때 행동의 방식·대상(순차적으로, 즉시, 어느 파드)은 그 행동과 같은 문장에 두고, 원문에 없는 단계나 지시는 추가하지 않습니다.
5. **다시 실행** — `total 0`이 나오거나 남은 항목마다 남길 이유가 있을 때까지 반복합니다.
6. **변경 내역 보고** — `writing-check`와 같은 형식으로 고친 내역을 붙입니다.
7. **용어집 제안** — 다른 문서에도 나올 묶음은 `docs/glossary.md`에 추가하자고 제안하고, 승인 후에만 추가합니다.

## 관련 스킬

- `writing-check` — 글을 점검할 때 이 스킬을 부릅니다
- `korean-humanizer` — 문체만 다듬을 때 씁니다
