# decision-write

작업 폴더의 `decisions.md`에 결정을 `Dec-N` 항목으로 기록합니다.
한 번 적은 결정은 고치지 않고, 바뀐 결정은 새 항목으로 덧붙입니다.

## 언제 사용하나요?

- plan-creator가 명확화 질문에서 정한 결정과 스스로 정한 결정을 남길 때
- TDD 중에 구현이 기존 결정과 부딪혀 결정을 바꿔야 할 때
- 작업 중에 새로 정한 것을 기록하고 싶을 때

## 트리거 문구

```
"결정 기록해줘"
"결정 추가해줘"
"이 결정 바꿔줘"
"Dec 추가"
```

## 실행 흐름

1. **작업 폴더 확인** — `docs/spec/{날짜}-{티켓}-{slug}/`. `decisions.md`가 없으면 `# Decisions` 제목만 넣어 만듦
2. **기존 결정과 비교** — `[SUPERSEDED by Dec-M]` 표시가 없는 항목(유효한 결정)과 부딪히는지 확인
3. **부딪히지 않으면** — 파일 끝에 다음 번호로 바로 추가
4. **부딪히면** — 멈추고 사용자에게 보고·초안 제안 → 승인되면 새 항목 추가 + 옛 항목 제목에 `[SUPERSEDED by Dec-N]`. 거절되면 기록하지 않음

## 항목 형식

템플릿은 `assets/decision-template.md`에 있습니다. 템플릿에 없는 칸(`비고` 같은)은 만들지 않습니다.

```markdown
### Dec-5. 판별 방식 — 키워드 1차 필터 + LLM 분류
영향도: significant · 출처: ai-suggested

문제 — LLM 분류 단독은 일 배치 비용 한도 초과
옵션
  (A) LLM 분류 유지 + 배치 주기 완화
  (B) 키워드로 후보 축소 후 LLM 분류
선택 — B
근거 — 호출 수 감소, 일 배치 주기 제약 유지
연관 설계 — Dec-2(대체) · Dec-3(검수 절차)
변경 히스토리 — Dec-2 대체, 사용자 승인
```

| 출처 | 제안 | 선택 |
|---|---|---|
| `user-suggested` | 사람 | 사람 |
| `ai-suggested` | AI | 사람 |
| `ai-selected` | AI | AI — 사용자가 먼저 검토할 대상 |

| 영향도 | 뜻 |
|---|---|
| `foundation` | 프레임워크 선택·핵심 구조처럼 다른 결정의 바탕 |
| `significant` | 여러 부분에 영향 |
| `local` | 한 단위에만 영향 |

## 지키는 규칙

- 기존 항목은 지우거나 고치거나 번호를 다시 매기지 않음
- 이미 정한 결정은 새 정보가 있을 때만 다시 논의
- Claude Code에서는 devlife 플러그인 hook이 기존 항목 수정을 사용자 승인 창으로 확인
