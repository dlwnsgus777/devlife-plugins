### 기존 코드의 함정

> 참조할 기존 구현에 결함이 있으면 여기 적는다. **적지 않으면 AI는 기존 코드를 "이 프로젝트의 정답"으로 읽고 그대로 복제한다.**
> 각 항목은 문제 진단으로 끝내지 말고 **`→ 신규는`까지** 쓴다 — 지시가 없으면 대안을 임의로 발명한다.

## 4. Verification

> 테스트 설명은 도메인 규칙 문장으로 쓴다. 테스트 결과에 표시되는 문장이다.
> 예: ~~"testCancelWhenPaid"~~ → **"결제 완료된 주문은 취소할 수 없다"**
> 1. Context의 모든 도메인 불변성이 여기 테스트로 한 번 이상 나와야 한다.
> 경계가 있는 규칙(기준 금액, 상한, 범위)은 경계마다 경계 값과 바로 앞 값을 기대 결과와 함께 적는다. 예: `199,999원 → 29,999원`, `200,000원 → 30,000원`
> - `[NEW]` — 다루는 기존 테스트가 없다. 새로 쓴다.
> - `[REGRESSION]` — 기존 테스트가 다룬다. 그대로 실행한다.
